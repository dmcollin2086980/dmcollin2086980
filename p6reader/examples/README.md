# HHK E Expansion example

`hhk_e_expansion.xer` is **not a Primavera P6 export**. It is a from-scratch
reconstruction of a client-provided PDF -- an Arviso Okland Construction JV
"Milestone & Takt Schedule" graphic for the "HHK E Expansion" project at
Gila River (revision date 2026-05-20, Takt start 2026-04-27) -- built to
give p6reader a large, plausibly-shaped file to load, summarize, check, and
export. **It does not validate real P6 format handling** and should not be
used as evidence that p6reader parses actual P6 exports correctly; see
`../docs/ASSUMPTIONS.md` for that gap.

Generated by `build_hhk_xer.py` (run with `python3 examples/build_hhk_xer.py`
from the repo root; it writes `examples/hhk_e_expansion.xer`).

## What came from the PDF vs. what was invented

Read directly off the PDF:

- The milestone summary table (phase start/finish dates and calendar-day
  durations for Preconstruction, each design phase, GMP/Buyout, and each
  construction phase -- Site, Core & Shell, Buildout, Finishes -- plus the
  Substantial/Final Completion dates).
- The design-row milestone and bar names and rough durations (Design & Trade
  RFP 5 wk, AHJ Permit ~10 wk, GMP/Buyout ~8 wk, HHK Approval ~4 wk).
- The procurement package list and lead-time weeks (Generators 62 wk down to
  Rebar 6 wk), each preceded by a ~6-week Prepare Shop Drawings step and a
  2-week Shop Drawing Approval step.
- The civil (15 wk: Makesafe/SWPPP/Fencing, Clear & Grub, Earthwork,
  Underground Utilities) and core/shell (Footings, UG MEP Rough-In,
  Waterproofing, Backfill, Slab On Grade, Erect Steel, Roofing, Prefab
  Panels) bar names and per-bar durations.
- The buildout/finishes takt-row abbreviation sequence for each of Areas
  01-08 and the closeout sequence (Final Inspections AHJ, COO, Owner
  Move-In, MEP Equip Rm Install, Air On).
- Most of the legend (re-cropped at 600 dpi): Design & Procurement legend
  (PSD, SDA, WO, F=Fabrication, D=Design/Delivery), Sitework legend (CG, UU,
  SB, P, L), Structural legend (SG, FF, CT, ES, DD, CM), Envelope legend
  (ED, R, SG=Storefront/Glazing, SD, MP), MEP legend (UG, OH, IWR, L, T,
  RTU), and Interiors/Finishes legend (F=Framing, DW, TF, PW, ACT, FL, T,
  S, MW, F=Finishes, CL, PP, P).

**Inferred / invented** -- flagged explicitly because this is where a
reconstruction like this is weakest:

- **Exact takt dates and week-by-week cell assignments.** The PDF's takt
  grid is a dense weekly-cell graphic; this build did not re-derive an
  exact calendar week for every cell. Instead, each takt-row code group was
  collapsed into one activity per contiguous run (e.g. "OHR x4" became one
  4-working-day activity) and areas were staggered by a flat 5-working-day
  offset. Real per-area start weeks almost certainly differ from this.
- **A handful of legend abbreviations used in the takt rows that don't
  appear in the (Design/Procurement, Sitework, Structural, Envelope, MEP,
  Interiors/Finishes) legend blocks at all** -- WL, EOH, OHR, FPPP, PWFS,
  MEPOH, MEPTRIM. These were guessed from context (their position in the
  row relative to legend-confirmed codes) and given descriptive names in
  the generator; they are not confirmed against the PDF.
- **All predecessor logic (FS/SS types and lag values).** The PDF shows bar
  positions on a timeline, not a P6 relationship network. Every
  predecessor/lag in `hhk_e_expansion.xer` was invented to reproduce
  plausible bar timing, not read off the graphic.
- **Both calendars** (5-day/8h for design, procurement, civil, and MEP
  equipment; 6-day/10h for core & shell and buildout/finishes field takt
  work) are inventions -- the PDF does not show a calendar definition.
- **Constraint dates** (`CS_SNET`, Start On or After) placed on each
  phase-start activity to anchor the generated network to the milestone
  table's dates.
- **Status/percent-complete** for the three activities that straddle the
  2026-05-20 data date (RFQ Due complete, Design & Trade RFP in progress
  at 30%, everything else not started).
- Early/late dates and total float were computed by a simple day-granularity
  forward/backward CPM pass written into the generator itself (see
  `build_hhk_xer.py`), using each activity's own calendar for its own
  duration/lag math. It is not P6's scheduling engine, and it does not
  account for a predecessor and successor having different calendars in a
  fully P6-accurate way.

## Known gaps in the reconstructed network

`p6reader check` on this file reports 16 Critical / 13 High / 187 Medium /
0 Low / 5 Info findings. Most of the volume is expected given the above --
a takt schedule collapsed into ~200 activities naturally produces long
procurement lead-time float and long core/shell/takt durations relative to
the tool's default 44-working-day thresholds. A few findings point at real
gaps left in this specific reconstruction (not planted, just not modeled):

- Several long-lead procurement deliveries (`ELEV-DEL`, `GLZ-DEL`,
  `REBAR-DEL`) and `CS-PANELS` were never tied to a specific installation
  activity, so they dangle as open finishes.
- Only the last buildout area's Finishes activity feeds Final Inspections;
  Areas 01-07's `*-FIN` activities are open finishes because no
  "all areas complete" tie-in milestone was modeled.
- `PM-CONST` (a Level of Effort general-conditions activity spanning
  construction) has a start tie (`SS` to Start Construction) but no
  successor, which is typical for LOE activities but still flagged as an
  open finish by the checker.

## Tool fix made while exercising this file

Loading/checking this file surfaced a real bug in `p6reader check`'s
open-start/open-finish rules (`p6reader/logic_check.py`): they treated
*every* `TT_Mile`/`TT_FinMile` activity in the schedule as if it were "the"
project start/finish milestone, so any ordinary activity whose only
immediate predecessor happened to be an interim phase-kickoff milestone
(e.g. `Program Complete`, `CD's Complete`) was wrongly flagged Critical.
Real schedules commonly have many such interim milestones. The fix narrows
"project start/finish milestone" to milestones that are themselves true
network sources/sinks (no predecessor, or no successor, of their own) --
this dropped the false-positive Critical count on this file from 28 to 16
and is covered by the existing `test_open_start_and_finish` test, which
still passes.

## Reproducing

```bash
python3 examples/build_hhk_xer.py
p6reader load examples/hhk_e_expansion.xer --out /tmp/hhk.db
p6reader summary /tmp/hhk.db
p6reader check /tmp/hhk.db --out examples/hhk_e_expansion_check.md --healthcare-overlay
p6reader export /tmp/hhk.db --format csv --out /tmp/hhk_out/
```
